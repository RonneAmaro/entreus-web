## Causa identificada

O comando local `node node_modules/typescript/bin/tsc --noEmit --incremental false` reproduziu os erros TS1434 na linha 204, TS1109 nas linhas seguintes e TS1160 em `.next/dev/types/routes.d.ts`.

O arquivo original encerrava corretamente `declare global` na linha 203, mas continuava com dez linhas residuais de um exemplo e de uma declaração já presentes acima. A linha 204 começava com `t async function GET(request: NextRequest, context: RouteContext<'/api/users/[id]'>) {`. O delimitador de Markdown desse exemplo, fora do comentário, também provocava o template literal sem fechamento. É corrupção do conteúdo gerado, não um erro de sintaxe de uma rota do aplicativo.

O artefato também estava obsoleto: a regeneração incluiu duas rotas já existentes, `/api/meet/rooms/[roomName]/messages/attachments/download` e `/api/meet/rooms/[roomName]/recordings/[recordingId]/download`. Nenhuma rota foi criada ou alterada nesta execução.

O `tsconfig.json` original inclui tanto `.next/types/**/*.ts` quanto `.next/dev/types/**/*.ts`; o `next-env.d.ts` original importa os tipos de desenvolvimento. Por isso um build que regenera os tipos de produção ainda podia falhar ao encontrar o artefato de desenvolvimento inválido. Essa inclusão foi preservada integralmente.

O gerador instalado usa `fs.promises.writeFile` em `node_modules/next/dist/server/lib/router-utils/route-types-utils.js`. A documentação instalada em `node_modules/next/dist/docs/01-app/03-api-reference/06-cli/next.md` descreve `next typegen` como o comando para regeneração independente. A evidência confirma o arquivo corrompido/obsoleto; não identifica qual processo histórico produziu a gravação inválida. Não se atribui a causa a concorrência sem comprovação.
